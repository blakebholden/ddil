# Multimodal + DLS (Jina) — Airgapped Setup (run on the box)

Stands up **Adventure 3 — Multimodal Intelligence**: a Jina omni embedding
server + two Elasticsearch indices on the kit. Two tracks:

- **Search by Image** (`jina-multimodal`, 768-d) — "type words, get pictures";
  text + image share one vector space. 10 synthetic shapes.
- **Need-to-Know** (`pmc-unstructured`, 1024-d) — 509 research papers under a
  fictional document-level-security model: hybrid RRF retrieval + cross-modal
  figures + a generative **Research Paper Analyst**, all enforced by clearance.

The frontend adventure + `/api/jina/*` router are already wired into the app.
This guide builds the omni server, the indices, and the data.

## Prerequisites

1. **Jina omni server running** on the GPU node, OpenAI-compatible on
   `192.168.1.20:8081`. From the `jina-airgap` toolkit (Ben's `~/Desktop/Jina`):
   - Bundle/load the **omni-small** image. **Blackwell (sm_120) needs a cu128
     build** — the prebuilt GPU images are cu121 and won't run; see the HPE
     build notes. Serve with `JINA_MODEL_ID=jinaai/jina-embeddings-v5-omni-small`.
   - Verify: `curl -s 192.168.1.20:8081/v1/embeddings -d '{"input":["hello"]}' -H 'content-type: application/json' | head -c 200`
2. **ES + Kibana up** (one-cluster topology). RRF retrievers need the
   **Enterprise/trial license** (the kit has it).
3. **Data staged on the box** (copy from `~/Desktop/Jina/demo-multimodal/`):
   ```
   /data/jina/manifest.json              # 10-doc track manifest
   /data/jina/images/*.png               # 10 synthetic shapes
   /data/jina/scale/hires_chunks.jsonl   # PMC text chunks (9,636)
   /data/jina/scale/hires_images.jsonl   # parent → figure paths (198)
   /data/jina/scale/extracted_imgs/...   # figure image files
   /data/jina/scale/samples/*.pdf        # source PDFs (served as /api/jina/pdf)
   ```
   These artifacts are gitignored; transfer by scp/USB.

## Run it

```bash
cd demo/scripts/jina
export ES_URL=http://192.168.1.20:9200 OMNI_URL=http://192.168.1.20:8081 EP=<es-password>

# 1. indices + ES inference endpoint + caption ingest pipeline
bash setup-indices-local.sh

# 2. 10-doc multimodal track (image vectors app-side, captions by ES)
python3 ingest-multimodal.py --data /data/jina

# 3. PMC research corpus + DLS markings (text + figures, 1024-d)
python3 ingest-pmc.py --data /data/jina/scale
```

`ingest-pmc.py` applies markings deterministically per `parent_id`
(`markings.py`) — distribution ≈ U 40% / CUI 25% / C 15% / S 13% / TS 7%, with
NOFORN/compartments at higher levels. Every chunk + figure of a paper shares its
marking, so need-to-know is consistent.

## Point the backend at local

Append the Jina block from `demo/backend/.env.airgapped` to `demo/backend/.env`
(media-mount paths must match where you staged the data), then restart the
backend. Verify:
```bash
curl -s localhost:8000/api/jina/state | python3 -m json.tool
curl -s localhost:8000/api/jina/analysts | python3 -m json.tool
# multimodal
curl -s 'localhost:8000/api/jina/multimodal/search?q=a+red+square' | python3 -m json.tool
# DLS — compare a public user vs senior analyst (accessible doc counts differ)
curl -s 'localhost:8000/api/jina/search?q=&analyst=public'  | python3 -c 'import sys,json;print(json.load(sys.stdin)["accessible"]["docs"])'
curl -s 'localhost:8000/api/jina/search?q=&analyst=ts_all'  | python3 -c 'import sys,json;print(json.load(sys.stdin)["accessible"]["docs"])'
```

Then in the app: **Multimodal Intelligence** → *Search by Image* (opener) and
*Need-to-Know* (switch analyst, watch the corpus + answers change).

## How the DLS enforcement works (for the talk track)

Every query — retrieval, figure strip, facet counts, and the generative answer —
runs through the same DLS pre-filter (`app/services/jina_dls.py`):
1. classification ≤ the analyst's clearance, AND
2. the doc has no compartments OR the analyst holds **all** of them (subset rule
   via `terms_set` + `compartments_count`), AND
3. NOFORN docs hidden unless the analyst is NOFORN-cleared.

The analyst literally cannot retrieve, cite, count, or have the LLM summarize
anything they aren't cleared to see — switching personas changes the visible
corpus size and every downstream answer.

## Caveats

- **One omni server, two dims:** omni-small is native 1024-d (used by
  pmc-unstructured); the 10-doc track requests `dimensions: 768` (Matryoshka
  truncation) to match `jina-multimodal` + the ES inference endpoint.
- **Markings are fictional** and generated by `markings.py` — not the source
  demo's exact assignments, but the same field schema and a realistic spread.
- The generative analyst uses the kit's local LLM (`gpt-oss:120b` via Ollama,
  `OLLAMA_LLM_URL`), grounded strictly in DLS-visible passages.
